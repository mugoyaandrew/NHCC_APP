Phase 1 — Enterprise Audit Trail 80%

Every create/update/delete operation is automatically logged via AsyncLocalStorage + Prisma $extends. Developers never need to manually write audit entries.

How It Works

  • async-context.js — Creates an AsyncLocalStorage that holds user ID, IP address, and User-Agent for each request
  • request-context.js — Express middleware that wraps every request in the AsyncLocalStorage context
  • prisma.js $extends — Intercepts every Prisma create/update/delete, reads the context, and writes an AuditLog row
  • audit.js route — GET /api/audit endpoint restricted to CEO and ICT roles

AuditLog captures

FieldDescription
userIdWho performed the action
operationCREATE / UPDATE / DELETE
modelWhich table/entity was affected
recordIdID of the affected record
changedFieldsJSON array of field names that changed
previousValuesFull JSON snapshot before the change
newValuesFull JSON snapshot after the change
ipAddressClient IP address
userAgentClient browser/app identifier

Phase 2 — Concurrent Data Protection 70%

Optimistic locking prevents data loss when two users edit the same record simultaneously.

Mechanisms Implemented

  • Version field — Every mutable model has a version column (default 1)
  • Optimistic locking — PUT requests check the submitted version against the DB version. If mismatched → 409 Conflict
  • Idempotency-Key middleware — Prevents duplicate form submissions. Caches the response for repeat requests with the same key
  • IdempotencyKey model — Compound unique on (key, userId, method, path)
Gap: Client-side doesn't generate Idempotency-Key headers yet. No ConflictDialog component. No concurrency integration tests.
